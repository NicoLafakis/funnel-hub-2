# AGENTS.md

Onboarding contract for AI agents (and humans acting like one) working in this repo.

## What Flywheel is

An eat-'em-up game (in the spirit of hole.io), now set across 10 stylized city metros (10 districts/levels each, 100 total), rendered in true 3D with a 3rd-person chase camera behind a visible avatar. Swallow city props — trash, bikes, cars, buses, buildings — and eventually each metro's landmark capstone. See [`README.md`](README.md) for gameplay, controls, and setup, and [`docs/city-3d-redesign-plan.md`](docs/city-3d-redesign-plan.md) for the full design rationale (formulas, tiers, metro table).

## Architecture in one sentence

Three.js (vendored as an ES module, no bundler) rendered via `<script type="module" src="src/main.js">` and an import map (`three` → `./assets/vendor/three.module.js`), with all game logic split across plain ES modules under `src/` (`engine/`, `data/`, `content/`, `systems/`, `meta/`, `ui/`). `index.html` is now just markup/CSS/overlays plus that one module script tag — no inline game logic. `scripts/` holds Node tools (serve, build, test, vendor-three, art-generation CLI). Still no backend/database, but there IS persistence now: `localStorage` (via `src/meta/save.js`) for coins, upgrades, unlocked-level, stars, achievements, the "Skyline-opedia" collection, and the player's owned/equipped avatar skins.

## Module map

- `src/main.js` — the only file that touches `document`/`window` at call time; bootstraps the engine once, wires every system together, and drives the screen flow (start → world map → level intro → play → done/fail → shop → next/win).
- `src/engine/` — `scene.js` (renderer/camera/clock; the light rig + `applyAtmosphere()`, which applies a metro's resolved atmosphere — sky, fog, ambient, sun, fill light, bloom — in one call at level start; and the postprocessing chain: `EffectComposer` + `BokehPass` depth-of-field whose focus main.js pins to the camera→avatar distance each frame, then a **selective bloom** combine. Bloom is selective by *geometry*, not luminance: `markBloomEmissive()` enables `BLOOM_LAYER` on genuinely emissive meshes (additive-blended materials, or `emissiveIntensity >= BLOOM_EMISSIVE_MIN` = 0.6 — which keeps 0.12-0.25 window bands out so lit buildings never blob), a second offscreen composer re-renders only that layer against black through `UnrealBloomPass`, and the result is added on top of the DOF'd frame. Addons are version-matched copies from `node_modules/three/examples/jsm`, vendored under `assets/vendor/postprocessing/` + `assets/vendor/shaders/` by `scripts/vendor-three.js` on every `npm install` — add a new addon to that script's `addons` list, never by hand-copying), `avatar.js` (player growth/movement, `radius() = 26 + sqrt(mass)*1.9`; it also owns SKIN APPLICATION — `createAvatar(scene, THREE, { skin })` and `avatar.applySkin(id)` restyle in place — materials are MUTATED, never replaced; a geometry is rebuilt only when its radius/segment key actually changes (and the outgoing one is disposed); the optional corona mesh is allocated lazily and fully disposed on the way out, so the default skin stays allocation-identical to the pre-skins avatar (2 meshes / 2 materials / 2 geometries). `applySkin` resets every avatar mesh to layer 0, because `markBloomEmissive` only ever ENABLES the bloom layer — main.js re-marks right after each equip, which is what lets Void actually stop glowing), `camera.js` (chase cam with obstacle-avoidance raycast), `input.js` (keyboard/pointer → normalized axes; main.js rotates them by camera yaw — `rotateAxesByYaw` — so WASD is camera-relative).
- `src/data/` — `formulas.js` (`target(n) = 1000*n²` and every other per-level curve: time, world size, tier, rival count, hazard density, capstone gate, item-value multiplier), `metros.js` (the 10 metros + landmarks + each metro's `atmosphere` block and the `atmosphereFor()`/`DEFAULT_ATMOSPHERE` resolver; `id`/`name`/`landmarkType` are a hard contract, pinned by a test), `levels.js` (`generateLevel(n)`/`generateAllLevels()`).
- `src/content/` — `propkit.js`/`landmarks.js`: procedural Three.js geometry (no external model downloads) for props and landmark capstones; `propkit.js` additionally maps PixelLab-generated PNG textures (`assets/textures/` — building facades, asphalt) onto building boxes and the ground plane via an optional `setPropTextures()` registry that main.js populates at bootstrap (headless tests never call it, so builders fall back to flat colors); `metroprops.js`: the per-metro prop VARIANTS (44 of them — Tokyo vending machines and noodle stalls, London black cabs and phone boxes, Paris Wallace fountains, NYC yellow cabs, Dubai palms, Roman Vespas, Rio cable-car pylons, Moscow Ladas, Sydney ferry bollards, Capital Prime hover-drones). `createPropMesh(kind, THREE, accent, metroIdOrOpts)` resolves METRO-FIRST and falls through to the generic prop for any metro/slot with no variant, so the registry is purely additive and the 3-argument signature is unchanged; a variant is a MESH SWAP ONLY (radius/mass still come from the level template, so the tier economy and eat-gate math cannot move) and must fill the same `DIMENSIONS` envelope, which a test pins. Anything authored at `emissiveIntensity >= 0.6` blooms for free via `markBloomEmissive`; `citylayout.js`: the deterministic, authored level-1 city (street grid, zoned blocks, park/parking-lot/plaza, street furniture) — pure data, no THREE import; `artmanifest.js`: pure resolution/fallback logic for the generated-art manifest (`assets/art-manifest.json` — per-metro world textures under `assets/textures/metro/<id>/` and UI icons under `assets/icons/`). main.js fetches the manifest at bootstrap, re-resolves the metro's texture set at every level build (session-wide texture cache, one fetch per file, shared originals never disposed), and re-registers it via `setPropTextures()` before props are built; any metro/slot/icon absent from the manifest falls back to the generic art (the manifest only ever lists verified on-disk PNGs, which is what makes fallback safe). Metro facades are cornice-to-cornice PANELS: main.js marks them `userData.facadePanel`, and propkit's `buildingBoxMaterials` maps them at whole repeats (one vertical panel per face) while generic tileables keep the original fractional repeat math.
- `src/systems/` — `audio.js`, `combo.js`, `achievements.js`, `swallow.js` (eat-gate math), `rivals.js`, `storms.js` — ported faithfully from the original 2D game (recoverable via `git show 97c9024:index.html`) and adapted to the 100-level economy — plus `debris.js`, the pooled destruction FX: swallowing a tier-5+ structure (`isDebrisWorthy`) fires a burst of chunks colored from that prop's OWN materials (`samplePropPalette` — brick brown, glass blue and glinty), flung outward + up, falling under gravity, tumbling and shrinking out. One InstancedMesh / one geometry / one material with a hard particle cap and FIFO recycling when full, so a long combo chain never allocates or adds a draw call. main.js creates it ONCE at bootstrap parented to the engine scene (never a level root), calls `clear()` per level build and `update(dt)` per frame.
- `src/meta/` — `save.js` (localStorage + in-memory fallback; the `flywheel.save.v1` schema now also carries `ownedSkins`/`equippedSkin`, both ADDED not renamed, so a pre-skins save loads with every byte of progress intact and simply arrives on the default skin), `upgrades.js` (5 tracks: size/speed/magnet/time/growth), `collection.js`, `worldmap.js`, `skins.js` (the 7 unlockable avatar vortex skins — pure data + resolvers, no THREE import). A skin is a COMPLETE VISUAL RECIPE (`core`/`rim`/optional `corona`) and can never touch a gameplay number: the core sphere's radius is a constant in `avatar.js`, deliberately NOT a skin field, so no skin can make the avatar look bigger than the radius it swallows with (a test pins this across every skin, at construction and across a runtime swap). Emissive intensities are authored against Phase 3's `BLOOM_EMISSIVE_MIN` (0.6) rather than forced with the `userData.bloom` escape hatch — Void sits at 0.35 with a normal-blended rim (the one skin that produces zero bloom anywhere), Supernova at 2.4. Unlock routes: coins in the shop (450/750/1200, priced inside `upgrades.js`'s 100-2500 band), one achievement (`combo25` → Void), two progress milestones (30 Skyline-opedia entries → Glacier Drift, 60 stars → Aurora Veil); `evaluateSkinUnlocks()` is idempotent and never auto-grants a coin skin, so main.js can call it after any progress event.
- `src/ui/` — `overlays.js`: generic overlay show/hide, the shop renderer (upgrade tracks now show their generated pixel-art icon when the manifest has one, emoji fallback otherwise), the skin-picker renderer (`renderSkins()` — reuses the SAME `.shoptrack` row idiom as the upgrade tracks; locked rows state HOW they unlock, with live milestone progress), `renderCollection()` (the Skyline-opedia album screen — icon card per CITY_QUIPS entry, reached from the world map; locked entries dim the icon to a silhouette with '???'), and `updateHUD()`. Achievement unlock toasts also carry their generated icon; every icon renders with `image-rendering:pixelated` and a missing icon renders exactly the pre-icon UI.

**Architectural rule that must hold for every module**: no browser-only API (`document`/`window`/`localStorage`) may be touched at module top level — only inside exported functions — so every file stays `import()`-able headlessly under plain Node (no DOM/GPU needed; Three.js geometry/Object3D construction needs no GPU context, only `WebGLRenderer.render()` does). This is what makes the test suite possible without a browser.

## Run / test

```bash
npm install                  # postinstall vendors three.module.js + the postprocessing/shader addons into assets/vendor/
npm start                    # serves at http://localhost:3003
npm test                     # 187-check headless suite (formulas, metros/atmospheres, levels, save/upgrades, avatar skins registry + unlock conditions + persistence + leak-free swap + zero-gameplay-effect invariant, scene graph, selective-bloom marking, city layout, metro prop variants + generic fallback, debris pool cap/recycling/disposal, swallow math, achievements/combo, art manifest + per-metro texture/icon resolution + fallback, audio)
npm run build                # copies index.html + assets/ + src/ into dist/
```

## Hard rules

- **Never commit `.leonardo-key`.** It's gitignored. The Leonardo AI API key comes only from the `LEONARDO_API_KEY` env var or that gitignored file — never hardcode it anywhere, including scripts or commit messages.
- **Run `npm test` before committing** any change under `src/` or to `index.html`. All 187 checks must pass. The suite imports the real modules directly (`import()` in plain Node) — it no longer regex-extracts a script tag, so splitting logic across files is expected and fine.
- **Run `npm run build` before pushing** — it now also copies `src/` into `dist/`, so a missing/renamed file under `src/` will surface there.
- **Static-only.** Don't introduce a backend, database, or server-side dependency. Persistence is `localStorage` only, client-side.
- **Keep THREE as dependency-injected**, not re-imported per module. `src/main.js` does the single `import * as THREE from 'three'` and passes that instance into every factory (`createEngine`, `createAvatar`, `createPropMesh`, etc.) — don't add a second `import * as THREE from 'three'` inside a new module.
